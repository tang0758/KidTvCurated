1. 背景与问题

1.1 起点

家里电视是海信 55E3F-MAX（VIDAA / Android 9 / MTK9652 / 2.5 GB RAM / 1080p），片库在绿联 UGOS Pro NAS 上（192.168.31.72），核心是约 1970 个儿童视频文件：分级动画、英语启蒙、纪录片、识字课。孩子 5 岁半。

在自研之前，依次试过三种方案，都不成立：

方案 实测结果 根本问题
Kodi 21.3 + TMDB 刮削 需打补丁绕过被墙域名；1970 文件扫库不稳；2.5 GB 内存吃紧；孩子能从「文件浏览」看到全部片库 内容边界不可控，维护成本高
Nova Video Player 全量刮削导致错配、扫描不稳定 同上，且不可离线可控
各视频 App 自带推荐 首页推荐、自动连播、广告 观看决定权在平台，不在家长

1.2 真正的需求

不是「做一个播放器」，而是三件事：

  1. 内容白名单：电视上只出现家长挑过的内容，不扫全盘、不联网刮削、不被推荐算法带走。
  2. 规则可执行：每天先看完家长指定的几集，才能看动画片；到点自动锁屏；时长有上限。
  3. 维护成本接近零：家长在电脑上双击一个 bat 就能改片单，改完电视自己更新，不需要遥控器操作、不需要重装 App。

1.3 已发生过的真实故障（产品的由来）

这些事故直接塑造了今天的架构，也是测试重点：

  • 保存片单后全站无法播放（两次）：SMB 单连接被并发读挂死，只能重启 App。
  • 目录名含 + 的整季动画全部打不开：URL 解码把 + 变成空格。
  • 家长在编辑器里上移三行，电视上封面与标题整体错位：条目 id 用了数组下标。
  • 一次手工填写掩码密码，把 ******** 写进 NAS，电视永久连不上自己。
  • 用 scrcpy 高分辨率软编压测后，电视所有视频黑屏（含优酷），只有整机断电才恢复。

2. 产品定位与设计原则

一句话定位：给家庭电视用的「家长编排型」儿童点播应用——电视端离线直读 NAS，家长在电脑/手机上编排，规则落在同一份 tv.json 上。

设计原则（冲突时的取舍依据）

# 原则 具体表现 代价（已接受）
P1 白名单优先 不扫全盘、不联网刮削、不截帧；只显示清单条目 没配封面就是灰卡，不会自动出海报
P2 单一事实来源 片单、时段、PIN、应用入口全部落在 NAS 的 data/curated/tv.json；电视端设置也写回它 强依赖 NAS 可写共享；写坏会自锁（已加双层占位符保护）
P3 家长零学习成本 双击 bat 开编辑器；电视端设置页方向键 + OK 高级字段仍需理解 JSON（保留原文编辑兜底）
P4 失败要能自愈 缓存兜底、SMB 硬超时重连、播放三层重试、NAS 换 IP 自发现 逻辑复杂度上升，日志点多
P5 系统改动必须可逆 默认桌面、停用 Aerial、appops 授权全部附撤销命令 需要家长能跑 adb（提供一键脚本/文档）

3. 用户与使用场景

3.1 角色

角色 画像 使用设备 核心诉求
家长（主要操作者） 本文档读者；懂一点电脑，不写代码 Windows PC、手机浏览器、电视遥控器 5 分钟内加一部新动画；能远程限时；出事能自己救回来
孩子（5–7 岁） 认字不多，只会方向键 + OK 电视 + 遥控器 打开就能看；看完有盖章和勋章
系统 / 运维（家长兼任） 会 adb 更好，不会也能用 PC + 局域网 安装、设为默认桌面、排障

3.2 关键场景

场景 触发 期望结果
S1 每晚例行 17:30 孩子开电视 主界面出现「今天要看的」，看完 5 集自动盖章，动画片解锁
S2 加新片 家长下载了新动画到 NAS 电脑双击编辑器 → 勾目录 → 保存；电视 15 秒内出现新卡片，无需遥控
S3 到点收工 20:30 或 60 分钟用尽 播放中断，锁屏左 42% 大倒计时、右 58% 学习角；孩子翻不出去
S4 家长临时加班 孩子还想看 15 分钟 锁屏按菜单键输 PIN（或直接按数字键）→ 放行 15 分钟
S5 出门在外改片单 家长在公司 手机经 Tailscale / UGREENlink 打开控制台改 tv.json；电视照常内网播放
S6 家长自己要用电视 要看新闻/装应用 菜单 → PIN → 退出到桌面（默认放行 30 分钟），回来可提前结束放行
S7 换 NAS / 换 IP 路由器重启、NAS 改地址 电视自动扫本网段找到 SMB 主机；失败则用缓存清单照常显示
S8 故障恢复 播放黑屏 / 列表卡死 按文档断电重启 / 清缓存 / 恢复备份，不丢打卡与进度

4. 目标与成功指标

4.1 北极星指标

从「家长在电脑上点保存」到「电视上看到新内容」的时间 ≤ 60 秒，且家长全程不碰遥控器。

当前实测：轮询通道 15 秒内生效；广播通道约 8 秒；两者互为兜底。

4.2 指标体系

维度 指标 目标 当前
稳定性 冷启动成功率 ≥ 99% 达标（无 AndroidRuntime 崩溃记录）
稳定性 单次播放起播成功率（含自愈） ≥ 99% 修复后实测 1.4 s 起播、0 错误
稳定性 「保存片单后全站卡死」 0 次/月 已修（硬超时 + 独立连接），连续 20 次覆盖写无异常
效率 新增一部动画的操作步数 ≤ 6 步 6 步（编辑器勾选 → 保存）
效率 片单变更到电视可见 ≤ 60 s 8–15 s
效果 每日必看完成率 ≥ 80% 待持续观察（打卡墙已具备统计）
效果 家长临时放行频次 记录并观察 待观察
体验 误锁（家长自己被锁） 0 次/周 设置页免锁 + 放行窗口已覆盖
维护 每月人工维护时长 ≤ 10 分钟 封面需手动生成（懒人版一键）

5. 范围

5.1 In Scope（本期）

  • Android TV 端 App（海报墙、剧集、播放、打卡、勋章、锁屏、家长菜单、设置页）
  • tv.json 片单协议与字段体系（分区、门禁、时段、学习角、儿童锁、应用入口、自动刷新）
  • 编排工具三件套：简易编辑器（8787）、网页控制台（8765）、PC 桌面助手（exe）
  • 封面批量生成、内置 255 张离线学习卡、50 幅名画
  • 部署与运维：Docker 常驻 NAS、UGOS Pro 部署包、Tailscale / UGREENlink 外网访问
  • 儿童锁：应用内拦截 + 默认桌面 + 前台守卫 + 开机自启（受固件限制）

5.2 Out of Scope（明确不做）

不做 原因
在线影视 / 内容分发 版权与合规；产品只做「自家片库的入口」
联网刮削海报、自动识别剧名 违背 P1（离线可控）；改由 make_covers.py 截帧生成
多娃档案 / 账号体系 当前只有一名使用者；复杂度收益比不划算
安卓原生编辑器 App 手机浏览器 + 添加到主屏幕已够用
iOS 端 无使用场景
家长 PIN 加密存储 PIN 只防孩子随手解锁，不是安全边界（已在文档声明）
拦截 Home / 输入源 / 电源等硬件键 Android 与红外固件层面不可达（见 12.2）

8. 功能需求

优先级：P0 = 不做产品不成立；P1 = 核心体验，缺失会明显掉档；P2 = 增强。
每条含验收标准（AC），可直接转为测试用例。

8.1 内容与播放

FR-01 片单加载与离线兜底（P0）✅

描述：App 启动时从 NAS 读取 <playlistShare>/curated/tv.json（默认 data:/curated/tv.json），解析为分区与条目。

规则
- 读取顺序：data → 主共享 → 普通数据 → 迅雷下载，记住首次成功者。
- 读不到时回退本机 playlist_cache，界面提示「正在使用上次的清单」，功能不中断。
- 读取使用独立短连接 + 硬超时（25 s），不占播放主连接。
- 445 连不上时扫本网段找 SMB 主机（10 分钟冷却，播放中不扫）。

AC
1. 正常网络下冷启动 ≤ 3 s 出现第一屏海报。
2. 拔掉 NAS 网线后重启 App，仍显示上次清单，顶栏有离线提示，不白屏、不崩溃。
3. NAS 改 IP 后（同网段），App 能自动连上新地址，无需改配置。

FR-02 海报墙（P0）✅

描述：按 sections 顺序渲染分区行，每行默认 5 张卡（columns 可改），卡片显示封面或标题占位。

规则
- 焦点：放大 1.10 + 金色描边 + 同排其它卡压暗至 0.72；分区标题同步变金。
- 卡片副标题显示集数（如「85 集」）。
- 空清单显示引导文案（「请在 NAS 的共享文件夹里放一份清单」）。
- 不联网、不刮削；封面只用 NAS 上现成图片（见 FR-16）。

AC
1. 遥控器上下切分区、左右选片，焦点清晰可见（3 米外可辨）。
2. 从播放页/剧集页返回，焦点回到离开时那张卡（不是「我的奖励」）。
3. 空清单时显示引导文案而不是空白页。

FR-03 剧集列表（P0）✅

描述：folder 条目进入剧集列表，递归最多 3 层子目录（剧名/第N季/单集.mp4）。

规则
- 文件扩展名白名单（mp4/mkv/avi/ts/mov/m4v/webm 等）；mp3 不进列表。
- 显示「共 N 个」，已看过的显示进度条/完成标记。
- 读取失败显示「读取超时，按遥控器 OK 重试」，可重按。

AC
1. 「数字积木」类多层目录能列出全部 181 集。
2. 目录名含 +、中文、空格、括号时可正常列出并播放（不得二次 URL 解码）。
3. 超过 3 层的目录不会被无限递归，最多 3 层。

FR-04 播放与续播（P0）✅

描述：内置 ExoPlayer 直读 SMB，支持暂停、快进/快退 15 秒、续播。

规则
- 每 3 秒批量落盘播放位置；再次进入从上次位置继续。
- 进度 ≥ passRatio（默认 92%）标记完成。
- 遥控器：OK 暂停/继续；左右 ±15 s；返回退出。
- 播放期间暂停轮询与封面加载（SmbPlaybackContext.playing），避免抢连接。

AC
1. 1080p H.264 起播 ≤ 2 s（正常网络，实测 1.4 s）。
2. 中途退出再进入，从上次位置继续（误差 ≤ 5 s）。
3. 播放中每 15 s 的片单轮询不得造成卡顿或断流。

FR-05 每日必看门禁（P0）✅

描述：gate: true 的分区为「每日必看」；requires: "<key>" 的分区在该 gate 全完成后解锁。

规则
- 完成判定：条目进度 ≥ passRatio，或手动看完（进度到结尾）。
- 未完成时，被锁分区卡片显示锁标 +「还差 N 个才解锁」。
- 家长可「这次先跳过必看」（仅本次会话有效，重启恢复）。
- 无 gate 分区时，所有分区随时可看。

AC
1. daily 5 条全部完成后，动画片/纪录片/学习三个分区立即解锁且可进入。
2. 未完成时点锁住的卡，提示「先做完上面那 N 个，就能看了」，不进入。
3. 「这次先跳过必看」后立即解锁；重启 App 后恢复限制。

FR-06 打卡墙（P1）✅

描述：当天必看全部完成时自动盖章；月历可翻页，显示连续天数与最长连击。

规则
- 盖章幂等：同一天只盖一次。
- 连续天数按自然日计算，中断即归零；历史最长连击单独保存。
- 进入奖励页即可查看，主界面完成后弹鼓励语。

AC
1. 首次完成必看，当天格子出现印章，连续天数 +1。
2. 同一天重复看完不会重复盖章。
3. 中间漏了一天，连续天数从漏掉那天起归零（最长连击保留）。

FR-07 勋章墙（P1）✅

描述：10 枚成就勋章，按累计打卡、连击、观看时长、视频数解锁；新解锁在主界面按钮挂小红点。

勋章 条件
启程之星「初」 首次完成每日必看

9. 关键业务规则（实现契约）

ID 规则 说明 / 边界
R-01 条目 id 由路径派生 形如 p:folder / p:file / p:app 加路径；不得用数组下标（会导致封面/进度错位）。旧键由 migrateLegacyKeys 一次性迁移
R-02 路径相对 nas.share 中文直接写，不 URL 编码；/ 分隔；自动剥离 共享名/、smb://host/share/ 前缀
R-03 不在 Uri.path 后再 URLDecode + 必须保留原义，否则整目录失效
R-04 完成判定 进度 ≥ passRatio（默认 0.92）；passRatio 以 Double 写入，避免浮点脏值
R-05 必看完成 gate 分区内全部条目 done；随之解锁 requires 指向的分区
R-06 打卡幂等 自然日唯一；连续天数按自然日；最长连击单独存
R-07 时长统计 仅播放中累计（暂停/缓冲不计），3 s 批量落盘
R-08 时段判定 左闭右开；结束 < 开始视为跨零点；weekend 缺省沿用工作日，[] = 全天
R-09 放行优先级 家长临时放行 > 时段/时长限制；放行期间不弹锁屏、不被前台守卫拉回
R-10 应用入口解锁 showAfterDaily 且存在 gate 分区 → 必看完成后可用；否则一直可用
R-11 PIN 4–8 位数字；明文存于 tv.json；仅防孩子随手解锁
R-12 密码占位符 空 / 全星号 / __KEEP_NAS_PASSWORD__ → 沿用旧密码，电视端同样保护
R-13 单一事实来源 时段/上限/PIN/apps 以 NAS tv.json 为准；电视本地只存运行态（进度、打卡、勾选、放行）
R-14 写回必须合并 读远端最新 → 只改目标字段 → 备份 → 原子写 → 回读校验
R-15 播放优先级 播放期间暂停轮询与封面加载，避免抢 SMB 连接

  • 电视端设置写回失败不得修改本地显示。

11.4 安全与隐私

  • tv.json 含 NAS 明文密码与 PIN，只放在自家 NAS；不入 Git、不外传。
  • 控制台默认只听 127.0.0.1；开 --lan 后所有 API 需访问码；连错 5 次锁 5 分钟。
  • 访问码存浏览器 localStorage，不进 URL / 历史 / 代理日志。
  • 禁止把 8765、5555 映射到公网；外网只用 Tailscale / UGREENlink / Cloudflare Access。
  • APK 内凭据为兜底，仓库只留占位符。

11.5 可维护性

  • 字段手册（CONFIG.md）、JSON Schema、内置题库自检脚本、编辑器自检（--self-test）。
  • 所有系统级改动均附撤销命令。
  • 关键链路（轮询/广播/写回）有日志与「电视状态」可视化诊断。

11.6 成本

  • 零订阅、零云服务费；仅家庭 NAS 电费与带宽。
  • 外网方案 A 免费；B 依赖已有绿联账号。

12. 约束与已知限制

12.1 技术约束

  • 电视只有 2.5 GB RAM，/data 可用曾低至 842 MB（装 Kodi 时 877 MB）→ APK 控制在 ~27 MB，不引入重型框架。
  • Android 9 不支持 scrcpy 音频转发（需 11+）。
  • smbj 的 withTimeout 管不住 TCP 半开与 oplock 等待 → 必须自建 deadline。

12.2 平台限制（不做承诺）

限制 影响 现状
Home 键由系统独占 只改 App 拦不住 通过“设为默认桌面 + 前台守卫”解决
VIDAA 不派发 BOOT_COMPLETED 给第三方 开机停原生桌面 按一次 Home 进入；已接受
输入源 / 直播 / 电源为红外/固件级 应用收不到按键 物理遮挡或简易遥控器
电视启用 FLAG_SECURE 截屏/投屏视频层黑屏 排障看 logcat，不看截图
视频共享只读 不能往旁边放封面 封面统一放 data:curated/covers/
厂商桌面/守护会抢前台 首选桌面被覆盖 停用 Aerial（可逆）

14. 风险登记册

# 风险 影响 概率 对策 是否已发生过
R1 SMB 单连接挂死导致全站无响应 高 中 硬超时 + 独立短连接 + 播放期让路 ✅ 2 次，已修
R2 scrcpy / 高负载压测卡死解码链路 高（需断电） 低 脚本硬警告，禁止提高分辨率/帧率 ✅ 1 次
R3 密码占位符写坏导致自锁 高 中 双层占位符保护 + 现场恢复流程 ✅ 1 次
R4 条目 id 用下标导致封面/进度错位 中 中 路径派生 id + 迁移 ✅ 1 次
R5 路径含 + 被解码成空格 中 低 删除二次 URLDecode ✅ 1 次
R6 Aerial 守护抢默认桌面 中 高（若未停用） 停用 Aerial（可逆） ✅
R7 电视存储不足导致安装失败 中 中 pm trim-caches；APK 控制体积 ✅
R8 NAS 换 IP / 待机后 ADB 关闭 中 中 自动扫描 + DHCP 保留建议 ✅
R9 编辑器/控制台暴露到公网 高（凭据泄露） 低 文档强禁止 + 访问码 + 限速 未发生
R10 内置图片过多导致内存压力 中 低 缩略图 + LruCache + 采样解码 未发生

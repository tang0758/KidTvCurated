## RQ-001 · 学习区改进：配图帮助理解 + 古诗「念诗」

- **登记**：2026-11-11，家长口述
- **状态**：待确认
- **原话**：
  1. 「学习区改进，文字和英文可以学习加图片帮助理解。」
  2. 「古诗可以加一个念诗的操作。」

### 现状（登记时）
- 锁屏「等待时间学习角」见 PRD **FR-09**：共 255 张内置卡 —— 57 首唐诗、78 个 A–Z 单词、
  50 幅名画、70 张识字/成语/短句，四类按 `order` 交错轮播，默认 20 秒一张。
- `LearningCard` 已有 `image` 字段，支持 `asset:xxx`（APK 内置图）与 `smb:xxx`（NAS 图片）；
  **目前只有名画卡（ART）用到它**，识字/成语/短句（TEXT）和单词（WORD）、古诗（POEM）都是纯文字。
  名画走 `ArtImages`（采样解码 + 12MB LruCache + 单后台线程），`learning.artFolder` 已能从 NAS 目录
  覆盖名画图 —— 这是「在线拉图」的现成先例。
- 锁屏遥控器按键已被占用（`LockActivity.onKeyDown`）：◀▶ / OK / 回车 / 下一首 → 翻页，
  播放·暂停 / 空格 → 暂停轮播，菜单键 + 数字 PIN → 家长放行，返回键吃掉。
- ROADMAP 第 12 节「明确不做」里有 **「语音交互 / TTS 朗读」**（理由：电视无麦克风、TTS 收益不确定）。
  本需求是**单向播放朗读**，不需要麦克风，与那条决策不完全等价，但涉及 TTS，评估时要一并复核。

## RQ-002 · 学习区资源改为在线拉取，不再编译进 APK

- **登记**：2026-11-11，家长口述
- **状态**：已排期（2026-11-17 并入 Wave 6 / **OPT-34** · **FR-35**，先打通 `learning.json` + 单词配图与 mp3 在线拉取，内置 78 词作断网兜底）
- **原话**：「学习区是否可以在线拉取。这样不用把资源编译到 apk 中。后台更好也更简单。」

### 现状（登记时）
- 文字类内容写在源码 `data/builtin/{Poems,Words,Arts,Texts}.kt`（合计约 412 行 Kotlin），
  `LearningLibrary` 是**离线**总入口；50 幅名画 jpg 放在 `app/src/main/assets/art/`（约 16 MB）。
  当前 debug APK 约 26 MB，名画图片占了主要头寸。
- 改内置内容 = 改 Kotlin 源码 → 重新打包 → 手动装 APK（见 ROADMAP 14 节发版流程），
  而电视上 v1.5~v1.9 一直没上，改内容的成本明显偏高 —— 这是本需求的痛点。
- 已有两条「在线」通道可复用：
  ① `tv.json` 的 `learning.custom` 可让家长追加自定义卡，`useBuiltin:false` 只用自定义；
  ② `learning.artFolder` + `ArtImages.bindNasArt()` 从 NAS 目录拉图片覆盖名画卡，
     `Smb.readAllIsolated()` / `Smb.withDeadline()` 是片单与图片的既有安全读取方式。
- 设计原则里「装上 APK 锁屏就能看」「断网可用」「只有自家 NAS 片库」是既有前提，
  改在线拉取要正面回答这些前提是否调整（PRD 第 2 节、FR-09 AC1）。

## RQ-003 · 视频图标缩小约 30%

- **登记**：2026-11-11 晚，家长口述
- **状态**：已排期（Wave 5 OPT-27 已缩至 `150dp`；2026-11-17 家长反馈可再调小一点点，排入 Wave 6 / **OPT-35**）
- **原话**：「视频图标缩小一些。缩小百分 30 都可以。」

### 现状（登记时）
- **初判落点：首页每个视频的海报卡**（`item_poster.xml`）：整卡 `200dp × 284dp`，
  `marginEnd 18dp` / `marginBottom 8dp`；`ivCover` 铺满卡片 `centerCrop`，底部压 110dp 渐变 +
  14sp 标题；进度角标 12sp。1080p 首屏一行大约 4 张（见工作区 `电视画面预览.png`）。
- **另一个可能**：分区标题旁的小图标 `ivSectionIcon`（`item_section.xml`）是 `22dp × 22dp`、
  `marginEnd 10dp`，来自 OPT-14 的 6 套矢量 `ic_sec_*.xml`，**只有家长在 `tv.json` 配了
  `section.icon` 才显示**；剧集页 `item_episode.xml` 是 76dp 纯文字行，没有图标。
- 焦点表现：`PosterAdapter` 在获得焦点时把整卡 `scaleX/scaleY → 1.10f`，失焦回 `1f`；
  放大所需留白靠 RecyclerView 的 padding（`item_section.xml` 的 `rvRow` 左右 12dp、上下 16dp）。
  **改卡片尺寸要连着复核这个放大与留白**，别让焦点金边/卡片被裁切（项目已有踩坑：
  焦点放大靠 padding，不要 `clipChildren=false`）。
- 缩 30% 若指整体等比：`200 → 140dp`、`284 → 199dp`，一屏可多放 1–2 张；
  标题/角标是否跟着缩要单独定。

## RQ-004 · 「继续看」是否应过滤掉已不在片单里的条目　→ **已关闭（功能移除）**

**结论（2026-11-12 09:30）**：家长直接决定**去掉整个「继续看」功能**（`v1.9.6(16)`），
本议题随功能一起消失，不再需要判断「要不要过滤」。以下保留原始发现，仅作留档。

**发现**（2026-11-12 07:48，第五轮实机收尾时）：家长在编辑器里把某分区条目从
`lv01-006~011` 换成 `lv01-012~018` 并保存，电视 15 秒内自动刷新（任务数 0/6 → 0/7）。
但首页「继续看」仍显示 `lv01-006 ABC Book Letter`（1 个）—— 它已经不在片单里了，
只有 `pos_` / `played_` 记录还在。

**现状**：`继续看` 来自本地记录（`pos_` / `played_` + `p:continue` 键），按路径派生 key 解析，
不校验该条目是否仍在当前分区列表里。文件若还在磁盘上就能继续播。

**待确认**：
1. 这是不是期望行为？家长「从片单里拿掉」的直觉通常是「不想让孩子再点它」；
2. 若应过滤：按「路径仍在当前片单任一 items 里」过滤，会不会把「家长只是暂时移出、
   孩子看到一半」的场景也一刀切掉；
3. 反向风险：文件被删但记录还在时点开会怎样（未验），是否该给「已找不到文件」的提示。

**影响面**：只涉及 `MainActivity` 的「继续看」组装逻辑与 `Store.allProgress()` 的调用点，不动计时账本。

## RQ-005 · 外网更顺手地配置「学习区」与「每日必看」

- **登记**：2026-11-13，家长口述
- **状态**：已实施（2026-11-19 `/grill-me` 对齐方案落地：电视端 `NetworkCallback` 连网秒级同步 + `learning.json` 纳入 15s 轮询 + `tv.ack.json` 回执 + 冷启动 `hasUnsyncedEdit` 一致校验；8765 控制台加 `tv.json` `baseHash` 409 冲突保护、`/api/sync-status` 回执展示与保存后自动跟踪、手机窄屏优化）
- **原话**：「我想外网更好控制配置学习区和每日必看，现在的办法是怎么做的」

### 现状（登记时，v1.9.6(16)）
- **没有独立的外网配置通道**：外网只改 NAS `data:curated/tv.json` 这一份文件，电视端
  `PlaylistSync.tick()` 每 15 秒自己来拉；电视不用改、也不用装东西（FR-18 仍是「具备方案，待部署验收」）。
- **每日必看** = `sections` 里 `key: daily` + `gate: true`，其它分区写 `requires: "daily"`。
  8765 控制台「片单编排」页可勾选，8787 简易编辑器也有「每日必看 gate」字段。
- **「学习区」有歧义**，待家长确认：① 锁屏右半边「等待时间学习角」= `tv.json` 的 `learning` 段
  （8765 控制台「等待学习角」页可配 enabled / intervalSeconds / order / stage / artFolder / custom；
  8787 无可视化页，只能在「JSON 原文」手改）；② 片单里标题为「学习」的普通分区。
- **外网链路**：控制台常驻 NAS Docker（`docker-compose.yml` / `docker-compose.tailscale.yml`）→
  手机经 Tailscale / UGREENlink / Cloudflare Tunnel 打开 `http://<地址>:8765/` → 访问码
  （16 位强码，连错 5 次锁 5 分钟，书签不带 `?k=`）→ 点「保存到 NAS」经 SMB 整份覆盖写
  `tv.json`，自动备份 `tv.backup.json`。红线：不映射 8765 到公网、不用 DDNS 裸奔。

### 现在「不好控」的四个点
1. **没有回执**：`control.json` 有 `control.ack.json`，`tv.json` 没有。网页只提示「已保存到 NAS」，
   外网看不到电视是否已应用，只能赌 15 秒。
2. **播放页不轮询**：`PlaylistSync.tick()` 在 `SmbPlaybackContext.playing` 时直接 return，
   退出播放才 `nudge()`；孩子在播时外网改动要等他退回首页。且 NAS 容器里没有 adb，
   发不出即时广播（`tvNotify` 只有 PC 上的 8787 简易编辑器有）。
3. **整份覆盖、无指纹比对**：网页 `/api/config` 是整份 JSON 覆盖，没有电视端
   `PlaylistWriter.pendingBaseHash` 那样的冲突检测；「先点重新读取」全靠人工纪律。
4. **学习角内容仍编译在 APK**：255 张内置卡在 `data/builtin/*.kt` + `assets/art/`，
   外网只能调 `learning` 参数与追加 `custom` 卡，换内置内容要重新打包（见 RQ-002）。
- **可借力**：`control.json` 走 `readAllIsolated()` 短连接，位于「播放中不轮询」判断之前，
  播放中也能 15 秒生效；但只有锁屏 / 解锁 / 加时 / 暂停四种指令，改不了片单内容。

## RQ-006 · 首页考虑「护眼模式」

- **登记**：2026-11-16 早上，家长口述
- **状态**：待确认（「护眼模式」具体形态未定）
- **原话**：「需求词加一个，就是在首页的时候，呃考虑护眼模式。」

### 现状（登记时，`2.0 (17)`）
- App **没有任何亮度 / 色温 / 夜间 / 护眼相关代码**：`AndroidManifest.xml` 只有
  `PACKAGE_USAGE_STATS / INTERNET / ACCESS_NETWORK_STATE / ACCESS_WIFI_STATE / WAKE_LOCK /
  RECEIVE_BOOT_COMPLETED`，**没有 `WRITE_SETTINGS`**；源码中也无 `screenBrightness`、
  暖色滤镜或夜间主题。
- 界面本来就是深色：`themes.xml` 的 `AppTheme`（`Theme.AppCompat.NoActionBar`）
  以 `@color/bg_deep` (`#0E1014`) 作 `windowBackground`，`activity_main.xml` 根布局同为 `bg_deep`；
  配色在 `colors.xml`（`bg_card #1A1D24`、`text_primary #F2F4F8`、金色 `accent #FFC44D`）。
  因此「刺眼」更可能来自白字 / 金色高亮 / 封面海报，而不一定是整屏亮度。
- 开关体系：`features.*` 默认值集中在 `Model.kt`（`autoNext` 默认关，`kioskPullback` /
  `remainingNotice` 默认开），改默认值须同步 `Model.kt` + 编辑器 normalize + `tv.schema.json`；
  设置页是 `SettingsActivity` 外壳 + `settings/` 五个分组，新增设置项只改分组的 `rows()`。
- 时段解析已有 `WindowMath.parse`（`18-20` 缺分钟 → null，起止相同按全天）；若做「晚上自动开」
  可复用，但计时/日期仍须走 `ClockGuard.day()` 与 `WatchClock`，别另起一套。

### 初判：三条实现路径（待选，未定方案）
1. **只调 App 窗口亮度**：`WindowManager.LayoutParams.screenBrightness`（0..1）不需要
   `WRITE_SETTINGS`，但只作用于本 App 窗口，海信 ROM 是否生效要实机验；改系统全局亮度需
   `WRITE_SETTINGS`（AppOps 授权，Android 9 普通应用通常拿不到）。
2. **首页叠一层暖色 / 低蓝光半透明 View**（琥珀色 + 可调 alpha）：改动最小、可回退，只在
   `MainActivity` 生效，**不污染播放页视频画面**（ExoPlayer SurfaceView 层级、`FLAG_SECURE`）；
   缺点是只压界面不压背光，深色底上效果有限。
3. **直接用电视系统自带的护眼 / 夜间 / 背光色温设置**：零开发成本；先实机确认 VIDAA

## RQ-010 · 提供 MCP Server，让 AI Agent 可定制内容与教材

- **登记**：2026-11-23，家长口述
- **状态**：已对齐定稿（2026-11-23 `/grill-me` 逐项拍板，待进 PRD / ROADMAP 排期）
- **原话**：「新增需求：做一个mcp，让agent可以通过mcp来定制内容和教材」；核心目标：「让 Agent 通过自然语言产生确定性的内容，按照必要的格式（JSON 规范格式）在显示系统上呈现」。

### 定稿方案（2026-11-23 `/grill-me` 拍板）

#### 1. 总体架构与部署路径
- **定位**：MCP Server 作为**「带 Schema 校验 + 预览状态机 + 版本快照」的受控写入层**，内部通过 HTTP 调用现有 8765 控制台 API（复用鉴权、`normalize`、`baseHash` 409 冲突保护、`tv.ack.json` 回执与 SMB 连接），**不绕开后台直写 NAS 底层文件**。
- **一期（MVP）**：独立轻量 Python MCP Server，先跑 **`stdio` 本地直连**，零侵入现有 `console.py` 主逻辑（仅在 L2 视频导入时按需补一个受控上传端点）。
- **二期**：增挂 `Streamable HTTP`（`/mcp`，复用 16 位强访问码），支持手机/远端 Agent 经 Tailscale 访问，兼容 NAS Docker 与 RQ-008 旧手机后端。

#### 2. 一期开放边界与工具契约（语义化局部工具，禁止整份 JSON 盲写）
| 分组 | 工具（示意） | 职责与约束 |
|---|---|---|
| **只读感知** | `get_schemas` | 返回 `tv.json`（分区/条目子集）与 `learning.json` 的严格 JSON Schema、枚举与字段约束 |
| | `get_current_config` | 读取当前片单（`tv.json`）、教材（`learning.json`）及 `tv.ack.json` 同步回执 |
| | `list_media` | 浏览/扫描 NAS 现有视频与封面目录（复用 `/api/browse`、`/api/scan`） |
| | `get_study_summary` | 只读 `GET /api/state`，返回脱敏后的掌握度（`LEARNING` / `MASTERED`）、打卡与观看摘要，**严禁任何写操作** |
| **教材定制（`learning.json`）** | `upsert_learning_cards` / `remove_learning_cards` | 模板化填槽增删改单词/识字/古诗/名画卡，由 MCP 按 Schema 确定性组装 |
| | `update_learning_policy` | 调整轮播策略、每日单词目标等学习参数 |
| **片单局部编排（`tv.json`）** | `set_daily_section` / `upsert_section` / `remove_section_items` | **仅限**编辑「每日必看（gate）」与普通分区条目、轮换规则；**代码级锁死** PIN、可看时段、每日时长上限、外部应用与 `features` 开关，防止误改 |
| **素材导入（双等级）** | `import_learning_image` / `import_media_video` | 见下方 L1 / L2 分级；另可复用 `/api/covers/generate` 生成视频封面 |
| **两段式发布与回滚** | `preview_change` | 对暂存变更执行 Schema 校验 + NAS 路径真实存在校验，返回结构化 **Diff + 校验报告 + `preview_id`**（校验失败直接返回逐字段错误让 Agent 重填，绝不落盘） |
| | `commit_change(preview_id)` | 经用户在对话里确认后执行：先存本地快照，再带 `baseHash` 调 8765 API 写回 NAS，并可选轮询 `tv.ack.json` 确认电视端生效 |
| | `list_revisions` / `rollback_revision` | 查看本地 `.mcp_revisions/` 最近 20 份带时间与摘要的快照，支持一键按快照带当前 `baseHash` 写回回滚 |

#### 3. 素材导入双等级（拍板）
- **L1（纯文字轻量级）**：外部 Agent 只产出结构化文字卡片或片单编排，发音直接填 `ttsText` 沿用电视端内部 TTS，零额外多媒体依赖。
- **L2（富媒体导入级）**：外部 Agent 已生成或准备好适合导入的图片/视频素材，经 MCP 受控导入到白名单目录并自动绑定进 `learning.json` / `tv.json`：
  - 配图导入：复用现有 `POST /api/learning/image`。
  - 视频导入：需在 `console.py` 补一个受控流式上传端点（如 `POST /api/media/upload`，限白名单视频扩展名 + 指定导入子目录 + 大小限制），避免绕开后台直写 SMB。

#### 4. 安全红线与约束
- **状态机硬门禁**：所有写入必须经过 `preview_change` → 用户确认 → `commit_change(preview_id)`，`preview_id` 与变更指纹及 `baseHash` 绑定，过期或远端变更触发 409 强制重新预览。
- **账本与规则隔离**：`state.json` 严格只读，不碰 `WatchClock` / `ClockGuard` / 锁屏防绕过门禁；`tv.json` 敏感控制字段（PIN、时段、时长上限）对 MCP 不可写；远程控屏（锁屏/加时）一期不开放。
- **版本快照**：存 MCP 本地 `.mcp_revisions/`（保留最近 20 份，不改动现有 NAS 目录结构，同时 8765 自身仍保留 `tv.backup.json`）。
- **Schema 单一真相源**：`tv.json` 沿用 `docs/tv.schema.json`，补齐 `docs/learning.schema.json` 作为教材校验与 `get_schemas` 的唯一依据。

### 验收基线（MVP）
1. 拿 5～10 条典型自然语言指令实测闭环（增删教材卡、按薄弱词出复习卡、编排每日必看、导入配图/视频、故意触发缺字段/不存在路径/超长文本被拦截并自动修正）。
2. 确认修改片单时不会丢失或篡改原有 PIN、时段、时长上限与无关分区。
3. 确认「preview → 确认 → commit → 电视 15s 内刷新并回写 `tv.ack.json` → rollback 回滚恢复」全链路跑通。
4. 纯逻辑校验、Diff 组装、快照管理具备 Python 单元测试并纳入 CI。

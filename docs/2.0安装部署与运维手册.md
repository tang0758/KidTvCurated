## 1. 版本概述与发版产物

小剧场 2.0 的主要能力：
- **互动学习角 2.0**：加权降频轮播、▲/▼ 掌握度标记与 `state.json` 同步、点读不计观看时长账本。
  ⚠️ 规划里的「卡片与多媒体在线拉取 / APK 瘦身」**这版并未落地**：电视端仍读内置 255 张卡，详见 3.3。
- **媒体内核**：4xxx 解码软解回退、ExoPlayer 切集复用、跳过片头片尾、变速与画面比例切换。
- **双模媒体网关**：HTTP 206 流媒体（优先）+ SMB（透明兜底），2026-11-15 修复后才真正生效，详见第 8 节。
- **极简运维**：8899 扫码配网、长按快捷管理、1080p 密度锁定、8765 网页控制台。

### 发版产物（本机实际口径）
| 产物 | 路径 | 说明 |
|---|---|---|
| **发版副本** | 工作区根目录 `小剧场.apk` | 真正 `adb install -r` 装到电视的包，**debug 签名** |
| 构建产物 | `curated-tv/app/build/outputs/apk/debug/app-debug.apk` | `./gradlew assembleDebug` 产出，复制到上一行即完成发版 |
| 学习卡库 | NAS `data:curated/learning.json` | 255 张卡，供 **网页控制台** 使用；电视端 2.0 不读它 |
| UGOS 部署包 | `curated-tv/dist/kidtv-console-ugospro.zip` | 生成后已铺开到 NAS `data:kidtv-console/`，容器按挂载目录运行 |

> `dist/KidTvCurated-v2.0-release.apk` / `-debug.apk` 这两个文件名是早期规划，本机并未产出。
> 离线 `assembleRelease` 会因 `lint-gradle` 未缓存失败；仓库 CI 与本机都只构建 **debug 包**。
> 发版后必须用 `aapt2 dump badging` 读**包内**版本号（别照抄 build.gradle），
> 并用 `apksigner verify --print-certs` 比对 debug 证书 SHA-256 `386f08ba…`，否则无法覆盖安装/降级。

## 2. 电视端安装与免遥控配网

### 2.1 安装方式

#### 方式 A：U 盘侧载
把根目录 `小剧场.apk` 复制到 U 盘，用电视自带的文件管理器/应用安装器安装。

#### 方式 B：局域网 ADB（推荐，本机实测口径）
```bash
export MSYS_NO_PATHCONV=1   # Windows Git Bash：带 /sdcard、/data/local/tmp 的 adb shell 前必做
ADB="D:/pcsoft/scrcpy-win64-v5.0.1/adb.exe"
"$ADB" connect 192.168.31.147:5555           # 本机电视实际 IP
"$ADB" shell dumpsys package com.family.curated | grep -E "versionName|versionCode|lastUpdateTime"
"$ADB" install -r "C:/Users/Stanley/WorkBuddy/2026-10-31-12-25-14/小剧场.apk"
```
- 装包**不抢前台**，但会杀掉应用进程，装完可能回到桌面；`adb install -r` 保留 `shared_prefs` 三份账本。
- 降级必须带 `-d`：`adb install -r -d <旧包>`。
- **周一至周五 09:00–18:00 不做装包测试**（会打断家人观看）；只读排查不受限。

### 2.2 免遥控扫码配网（OPT-29）
电视后台常驻轻量服务 **8899**，配网页是根路径：
```text
http://192.168.31.147:8899/          （不是 /pair）
```
表单提交后 `POST /api/nudge` 让电视 1 秒内热刷新片单；实测提交相同值返回 `Saved` 约 0.019s。
⚠️ **安全**：该页无鉴权且表单会回填 NAS 明文密码，仅限局域网，别做端口映射。

## 3. NAS 侧资源完整部署指南

### 3.1 目录结构（`data` 共享）
```text
data:\
 ├── curated\
 │    ├── tv.json                  # 核心片单与规则（改动前务必原字节备份）
 │    ├── tv.backup.json           # 自动备份
 │    ├── state.json               # 观看进度 / 打卡 / 掌握度双向备份
 │    ├── learning.json            # 255 张卡（控制台用）
 │    ├── covers\                   # 封面
 │    └── logs\                     # 诊断日志上传目录（自动生成）
 └── kidtv-console\                # 控制台容器项目（免 build 挂载模式）
      ├── docker-compose.yml        # 现为主配置（挂载 ./:/app）
      ├── docker-compose.nobuild.yml
      ├── Dockerfile
      ├── tools\console.py
      ├── tools\static\index.html
      ├── config\nas.local.json
      └── 使用说明.md
```
> ⚠️ `curated/learning/images\`、`curated/learning/audio\` **目前并不存在**。
> `learning.json` 里 255 条 `image` / `audio` 路径是导出脚本写的元数据，素材没有生成 —— 见 3.3。

### 3.2 `learning.json` 卡片库
```bash
python tools/export_learning.py     # → dist/learning/learning.json，255 张：57 诗 / 78 词 / 50 画 / 70 识字
```
上传到 `data:curated/learning.json`。`/api/learning` 从 NAS 读回 255 张，`source=nas`。
**电视端 2.0 源码不读这个文件**：锁屏学习角用 `data/builtin/` 编译进 APK 的内置卡库；
网页控制台「学习角 2.0」页目前也只编辑 `tv.json` 的 `learning` 段、没接 `/api/learning`。

### 3.3 图片与音频现状（2026-11-15 实机核对，重要）
| 项目 | 实际情况 |
|---|---|
| **名画图片** | **能用**。APK `assets/art/` 有 50 张公共领域名画（16 MB），`BuiltinCards.art()` 写入 `image="asset:<文件名>"`，50/50 文件名匹配。实机翻到「名画」卡可正常显示《最后的晚餐》等大图 |
| 文字卡配图 | 诗 57 / 单词 78 / 识字 70 共 205 张是**纯文字版式设计**；`showText()` 虽留了小插图位，但内置数据没给 `image`，所以不显示图。看起来「没有图片」多半是刚好停在文字卡 |
| 家长自定义图 | `learning.artFolder` / `artShare` 未配置 → `ArtImages.bindNasArt()` 不生效；配了 NAS 图片目录可覆盖名画卡 |
| **点读音频** | **完全没有资源**。255 张内置卡 `audio` 全为 null；APK 内 mp3/ogg/wav **0 个**；全仓无 `TextToSpeech` 调用（`ttsText` 只是数据字段）。`LockActivity` 在 `audio` 为空时走 `nextCard()`，所以按 OK 只是翻页 |
| 悬空路径 | `export_learning.py` 写的 `learning/audio/*.mp3`、`learning/images/*.jpg` 没有对应文件；给 ART 卡写的 `image="art/xxx.jpg"` 也缺 `asset:` 前缀，与 `ArtImages.load()` 的约定不一致 |

要让点读发声，需生成音频（或接系统 TTS 读 `ttsText`）、下发到 `filesDir/audio/` 或 NAS 并配 http URL，
同时给卡片补 `audio` 字段；用 `edge-tts`（`zh-CN-XiaoxiaoNeural` / `en-US-JennyNeural`）批量生成是可行方案。

## 4. 双模流媒体网关部署 (HTTP 206 加速)

### 4.1 服务与接口
NAS 上的 `kidtv-console` 容器跑 `python /app/tools/console.py --lan --no-browser`，监听 `0.0.0.0:8765`：
- `http://192.168.31.72:8765/?k=<访问码>` —— 网页控制台（访问码取本机 `curated-tv/.console_token`，**不写入文档**）
- `/api/desktop/ping` —— 电视网关探活（无需访问码）
- `/stream/<share>/<path>` —— HTTP 206 Range 视频流，**中文共享名要 URL 编码**
- `/api/learning`、`/api/config`、`/api/state`、`/api/nudge`、`/api/desktop/logs`

### 4.2 电视端路由（2026-11-15 修正后的口径）
- 探测**不是**「启动时/切集时」，而是每次 `MediaGateway.resolveMediaUri()`（起播、自动重试）被调用时；
  结果缓存 **60 秒 TTL**，只在内存里，不落盘。
- 缓存新鲜且 `true` → `http://<NAS>:8765/stream/<share>/<path>`；否则 `smb://nas/<path>`。
- 播放出错会 `markHttpUnavailable()`，TTL 内不再重试 HTTP；过期后自然重探。
- `gatewayPort` 未写进 `tv.json` 时用默认 **8765**。
- 运维看日志：`adb logcat -d | grep MediaGateway`，两条关键行
  `HTTP 媒体网关探测 … available=true/false` 与 `播放源 HTTP/SMB uri=…`。

### 4.3 UGOS Pro 容器部署踩坑（本机实录）
1. 项目向导只有「导入 Compose」：选 **「从 NAS」** → `data/kidtv-console/docker-compose.yml`；
   不要选「从本地电脑」（会把项目建到空目录，`build: context: .` 找不到 Dockerfile）。
2. Docker Hub 直连超时：在 Docker → 镜像 → 加速器配置加
   `https://docker.m.daocloud.io`、`https://docker.1ms.run`（NAS 实测可达）。
3. `pip install` 也要换源：`Dockerfile` 与免 build compose 已改 `-i https://mirrors.aliyun.com/pypi/simple/`。
4. UGOS 项目保存的是**创建时导入的 compose 快照**：改 NAS 上的文件不会重读，
   「重新部署」只做 `up -d`、不重新 build。改 compose 必须**删除项目重建**（删时选保留项目文件）。
5. 现主 `docker-compose.yml` 是**免 build 挂载模式**（`python:3.12-slim` + `./:/app` + `restart: unless-stopped`）：
   改 `tools/console.py` 后**重启容器**即生效，不用重建镜像。原 build 版备份在本机 `.workbuddy/tmp/backup-20261115-1455/`。
6. 注意 `zqtang` 的 SSH 是应用层权限，**不在 Linux `docker` 组**，`docker ps` 会报 socket 权限拒绝；
   容器重启要么在 UGOS 界面点，要么由管理员执行。

### 4.4 网关验证命令
```bash
# 探活与学习卡库
curl -s "http://192.168.31.72:8765/api/desktop/ping"
# 206（英文 share 与中文 share 都要测）
curl -s -H "Range: bytes=0-1023" -o /dev/null -w "%{http_code} %{size_download}\n" \
  "http://192.168.31.72:8765/stream/data/curated/tv.json"
# 电视侧最终播放源
adb logcat -d | grep MediaGateway
```
2026-11-15 实测：真实播放 URI 返回 `206 Content-Range: bytes 0-1023/3899219`、实收 1024 字节。
⚠️ `/stream/*` 在鉴权分支之前返回，局域网内可直接拉视频；访问码也偏短，放外网前要换强码并加鉴权。

## 8. 2026-11-15 网关 hotfix 变更记录

**问题**：实机起播日志恒为 `MediaGateway: HTTP 媒体网关探测 … available=false`，
8765 服务在线却永远走 SMB。根因是 `isHttpAvailable()` 在 `PlayerActivity.onCreate` 的**主线程**
直接发 `HttpURLConnection`，Android 抛 `NetworkOnMainThreadException` 被 `catch (_: Exception)` 静默吞掉。

**修复**（`MediaGateway.kt` + 新增 `GatewayMath.kt` / `GatewayMathTest.kt`）：
- 网络探测只跑在单条 daemon 后台线程 `gateway-probe`；主线程读缓存，缓存过期时
  `Future.get(1500ms)` 限时等结果（等待不是网络操作，不触发主线程限制），超时按 SMB 兜底。
- 缓存状态机抽到纯 Kotlin 的 `GatewayMath`（`fresh` / `shouldProbe` / `httpPreferred` /
  `recorded` / `invalidated`），覆盖 TTL 边界、时间回拨、降级后不重探等 11 条单测。
- `resolveMediaUri()` 增加 `播放源 HTTP/SMB uri=…` 日志，便于运维一眼确认路由。

**质量门禁**：单测 158（新增 11）全绿、PC 28 全绿、文案守卫 268 水位未升；
`aapt2` 2.0/17、`apksigner` 证书 `386f08ba…`；发版副本 sha256 `352b3ece…`，
设备包逐字节一致，三份 prefs 保留。

**实机复验（20:39）**：
```
I MediaGateway: HTTP 媒体网关探测 host=192.168.31.72:8765 available=true   (pid≠tid，后台线程)
I MediaGateway: 播放源 HTTP uri=http://192.168.31.72:8765/stream/%E5%84%BF%E7%AB%A5…/
```
播放中 1 条活跃音轨、退出后归零、无 FATAL；真实 URI 206 实收 1024 字节。
修复前同一用例为 `available=false` + `smb://`，对照见 `待实机验证.md` 第 14 节。

**顺带改动**：`tools/console.py` 的 `log_message` 增加 `/stream/` 留痕（便于从
`/api/desktop/logs` 判断电视走了哪条路），已同步到 NAS 挂载目录，
但容器内进程属 root、SSH 账号无 docker/kill 权限，**需下次容器重启后才生效**；
当前服务功能不受影响。

**遗留提醒**：播放日志里出现 `OMX.MS.AVC.Decoder` / `BadPortIndex(0x8000101b)`，
本次未卡死（能播能退、音轨正常）；若日后出现全视频黑屏，只能断电/重启。

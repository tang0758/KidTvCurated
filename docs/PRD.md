## 1. 背景与问题

### 1.1 起点

家里电视是海信 55E3F-MAX（VIDAA / Android 9 / MTK9652 / 2.5 GB RAM / 1080p），片库在绿联 UGOS Pro NAS 上（`192.168.31.72`），核心是约 1970 个儿童视频文件：分级动画、英语启蒙、纪录片、识字课。孩子 5 岁半。

在自研之前，依次试过三种方案，都不成立：

| 方案 | 实测结果 | 根本问题 |
|---|---|---|
| Kodi 21.3 + TMDB 刮削 | 需打补丁绕过被墙域名；1970 文件扫库不稳；2.5 GB 内存吃紧；孩子能从「文件浏览」看到全部片库 | 内容边界不可控，维护成本高 |
| Nova Video Player | 全量刮削导致错配、扫描不稳定 | 同上，且不可离线可控 |
| 各视频 App 自带推荐 | 首页推荐、自动连播、广告 | 观看决定权在平台，不在家长 |

### 1.2 真正的需求

不是「做一个播放器」，而是三件事：

1. **内容白名单**：电视上只出现家长挑过的内容，不扫全盘、不联网刮削、不被推荐算法带走。
2. **规则可执行**：每天先看完家长指定的几集，才能看动画片；到点自动锁屏；时长有上限。
3. **维护成本接近零**：家长在电脑上双击一个 bat 就能改片单，改完电视自己更新，不需要遥控器操作、不需要重装 App。

### 1.3 已发生过的真实故障（产品的由来）

这些事故直接塑造了今天的架构，也是测试重点：

- 保存片单后**全站无法播放**（两次）：SMB 单连接被并发读挂死，只能重启 App。
- 目录名含 `+` 的整季动画**全部打不开**：URL 解码把 `+` 变成空格。
- 家长在编辑器里上移三行，电视上**封面与标题整体错位**：条目 id 用了数组下标。
- 一次手工填写掩码密码，把 `********` 写进 NAS，电视**永久连不上自己**。
- 用 scrcpy 高分辨率软编压测后，电视**所有视频黑屏**（含优酷），只有整机断电才恢复。

## 2. 产品定位与设计原则

**一句话定位**：给家庭电视用的「家长编排型」儿童点播应用——电视端离线直读 NAS，家长在电脑/手机上编排，规则落在同一份 `tv.json` 上。

### 设计原则（冲突时的取舍依据）

| # | 原则 | 具体表现 | 代价（已接受） |
|---|---|---|---|
| P1 | **白名单优先** | 不扫全盘、不联网刮削、不截帧；只显示清单条目 | 没配封面就是灰卡，不会自动出海报 |
| P2 | **单一事实来源** | 片单、时段、PIN、应用入口全部落在 NAS 的 `data/curated/tv.json`；电视端设置也写回它 | 强依赖 NAS 可写共享；写坏会自锁（已加双层占位符保护） |
| P3 | **家长零学习成本** | 双击 bat 开编辑器；电视端设置页方向键 + OK | 高级字段仍需理解 JSON（保留原文编辑兜底） |
| P4 | **失败要能自愈** | 缓存兜底、SMB 硬超时重连、播放三层重试、NAS 换 IP 自发现 | 逻辑复杂度上升，日志点多 |
| P5 | **系统改动必须可逆** | 默认桌面、停用 Aerial、appops 授权全部附撤销命令 | 需要家长能跑 adb（提供一键脚本/文档） |

## 3. 用户与使用场景

### 3.1 角色

| 角色 | 画像 | 使用设备 | 核心诉求 |
|---|---|---|---|
| 家长（主要操作者） | 本文档读者；懂一点电脑，不写代码 | Windows PC、手机浏览器、电视遥控器 | 5 分钟内加一部新动画；能远程限时；出事能自己救回来 |
| 孩子（5–7 岁） | 认字不多，只会方向键 + OK | 电视 + 遥控器 | 打开就能看；看完有盖章和勋章 |
| 系统 / 运维（家长兼任） | 会 `adb` 更好，不会也能用 | PC + 局域网 | 安装、设为默认桌面、排障 |

### 3.2 关键场景

| 场景 | 触发 | 期望结果 |
|---|---|---|
| S1 每晚例行 | 17:30 孩子开电视 | 主界面出现「今天要看的」，看完 5 集自动盖章，动画片解锁 |
| S2 加新片 | 家长下载了新动画到 NAS | 电脑双击编辑器 → 勾目录 → 保存；电视 15 秒内出现新卡片，无需遥控 |
| S3 到点收工 | 20:30 或 60 分钟用尽 | 播放中断，锁屏左 42% 大倒计时、右 58% 学习角；孩子翻不出去 |
| S4 家长临时加班 | 孩子还想看 15 分钟 | 锁屏按菜单键输 PIN（或直接按数字键）→ 放行 15 分钟 |
| S5 出门在外改片单 | 家长在公司 | 手机经 Tailscale / UGREENlink 打开控制台改 `tv.json`；电视照常内网播放 |
| S6 家长自己要用电视 | 要看新闻/装应用 | 菜单 → PIN → 退出到桌面（默认放行 30 分钟），回来可提前结束放行 |
| S7 换 NAS / 换 IP | 路由器重启、NAS 改地址 | 电视自动扫本网段找到 SMB 主机；失败则用缓存清单照常显示 |
| S8 故障恢复 | 播放黑屏 / 列表卡死 | 按文档断电重启 / 清缓存 / 恢复备份，不丢打卡与进度 |

## 4. 目标与成功指标

### 4.1 北极星指标

**从「家长在电脑上点保存」到「电视上看到新内容」的时间 ≤ 60 秒，且家长全程不碰遥控器。**

当前实测：轮询通道 15 秒内生效；广播通道约 8 秒；两者互为兜底。

### 4.2 指标体系

| 维度 | 指标 | 目标 | 当前 |
|---|---|---|---|
| 稳定性 | 冷启动成功率 | ≥ 99% | 达标（无 AndroidRuntime 崩溃记录） |
| 稳定性 | 单次播放起播成功率（含自愈） | ≥ 99% | 修复后实测 1.4 s 起播、0 错误 |
| 稳定性 | 「保存片单后全站卡死」 | 0 次/月 | 已修（硬超时 + 独立连接），连续 20 次覆盖写无异常 |
| 效率 | 新增一部动画的操作步数 | ≤ 6 步 | 6 步（编辑器勾选 → 保存） |
| 效率 | 片单变更到电视可见 | ≤ 60 s | 8–15 s |
| 效果 | 每日必看完成率 | ≥ 80% | 待持续观察（打卡墙已具备统计） |
| 效果 | 家长临时放行频次 | 记录并观察 | 待观察 |
| 体验 | 误锁（家长自己被锁） | 0 次/周 | 设置页免锁 + 放行窗口已覆盖 |
| 维护 | 每月人工维护时长 | ≤ 10 分钟 | 封面需手动生成（懒人版一键） |

## 5. 范围

### 5.1 In Scope（本期）

- Android TV 端 App（海报墙、剧集、播放、打卡、勋章、锁屏、家长菜单、设置页）
- `tv.json` 片单协议与字段体系（分区、门禁、时段、学习角、儿童锁、应用入口、自动刷新）
- 编排工具三件套：简易编辑器（8787）、网页控制台（8765）、PC 桌面助手（exe）
- 封面批量生成、内置 255 张离线学习卡、50 幅名画
- 部署与运维：Docker 常驻 NAS、UGOS Pro 部署包、Tailscale / UGREENlink 外网访问
- 儿童锁：应用内拦截 + 默认桌面 + 前台守卫 + 开机自启（受固件限制）

### 5.2 Out of Scope（明确不做）

| 不做 | 原因 |
|---|---|
| 在线影视 / 内容分发 | 版权与合规；产品只做「自家片库的入口」 |
| 联网刮削海报、自动识别剧名 | 违背 P1（离线可控）；改由 `make_covers.py` 截帧生成 |
| 多娃档案 / 账号体系 | 当前只有一名使用者；复杂度收益比不划算 |
| 安卓原生编辑器 App | 手机浏览器 + 添加到主屏幕已够用 |
| iOS 端 | 无使用场景 |
| 家长 PIN 加密存储 | PIN 只防孩子随手解锁，不是安全边界（已在文档声明） |
| 拦截 Home / 输入源 / 电源等硬件键 | Android 与红外固件层面不可达（见 12.2） |

```
│   ├── SettingsActivity 家长控制（两列设置页，写回 NAS）
│   └── LockActivity     锁屏（左 42% 倒计时 / 右 58% 学习角）
└── 后台组件：KidApp（全局时间守卫 + 前台守卫）、PlaylistSync（轮询）、
    PlaylistChangedReceiver（广播）、BootReceiver（开机自启）

编排侧
├── 简易编辑器 tools/tvjson_simple.py   127.0.0.1:8787（日常主力，双击 start-tvjson-editor.bat）
├── 网页控制台 tools/console.py         127.0.0.1:8765（五页签，手机/PC 浏览器，可 Docker 常驻 NAS）
└── PC 桌面助手 tools/desktop.py        dist/KidTvConfig-PC.exe（内嵌同一控制台 + 二维码 + 日志）
```

### 7.2 观看状态机

```
            ┌────────────── 家长 PIN 放行 15 min ──────────────┐
            ↓                                                  │
[可用] ──时段外/时长用尽──> [锁屏 LockActivity] ──时长到/手动结束──┘
   │                              ↑
   │ 必看未完成                    │ 播放中到点
   ↓                              │
[门禁：其他分区上锁] ──必看全完成──> [解锁 + 盖章 + 勋章检查]
```

### 7.3 生效链路（改片单后）

```
编辑器/控制台 保存
   ├─ 备份 NAS 同目录 tv.backup.json
   ├─ 写 .tv.json.tmp → 原子 rename
   └─ 发显式广播 com.family.curated.PLAYLIST_CHANGED
                 ↓（失败也不要紧）
电视 PlaylistSync 每 15 s 读 NAS tv.json 全文 → 与缓存逐字比较
                 ↓ 内容真变了
Repo.load() → 复用 adapter 重绘（保留滚动位置、焦点、门禁状态）
```

## 8. 功能需求

> 优先级：**P0** = 不做产品不成立；**P1** = 核心体验，缺失会明显掉档；**P2** = 增强。
> 每条含验收标准（AC），可直接转为测试用例。

### 8.1 内容与播放

#### FR-01 片单加载与离线兜底（P0）✅

**描述**：App 启动时从 NAS 读取 `<playlistShare>/curated/tv.json`（默认 `data:/curated/tv.json`），解析为分区与条目。

**规则**
- 读取顺序：`data` → 主共享 → `普通数据` → `迅雷下载`，记住首次成功者。
- 读不到时回退本机 `playlist_cache`，界面提示「正在使用上次的清单」，功能不中断。
- 读取使用**独立短连接 + 硬超时（25 s）**，不占播放主连接。
- 445 连不上时扫本网段找 SMB 主机（10 分钟冷却，播放中不扫）。

**AC**
1. 正常网络下冷启动 ≤ 3 s 出现第一屏海报。
2. 拔掉 NAS 网线后重启 App，仍显示上次清单，顶栏有离线提示，不白屏、不崩溃。
3. NAS 改 IP 后（同网段），App 能自动连上新地址，无需改配置。

#### FR-02 海报墙（P0）✅

**描述**：按 `sections` 顺序渲染分区行，每行默认 5 张卡（`columns` 可改），卡片显示封面或标题占位。

**规则**
- 焦点：放大 1.10 + 金色描边 + 同排其它卡压暗至 0.72；分区标题同步变金。
- 卡片副标题显示集数（如「85 集」）。
- 空清单显示引导文案（「请在 NAS 的共享文件夹里放一份清单」）。
- 不联网、不刮削；封面只用 NAS 上现成图片（见 FR-16）。

**AC**
1. 遥控器上下切分区、左右选片，焦点清晰可见（3 米外可辨）。
2. 从播放页/剧集页返回，焦点回到离开时那张卡（不是「我的奖励」）。
3. 空清单时显示引导文案而不是空白页。

#### FR-03 剧集列表（P0）✅

**描述**：`folder` 条目进入剧集列表，递归最多 3 层子目录（`剧名/第N季/单集.mp4`）。

**规则**
- 文件扩展名白名单（mp4/mkv/avi/ts/mov/m4v/webm 等）；mp3 不进列表。
- 显示「共 N 个」，已看过的显示进度条/完成标记。
- 读取失败显示「读取超时，按遥控器 OK 重试」，可重按。

**AC**
1. 「数字积木」类多层目录能列出全部 181 集。
2. 目录名含 `+`、中文、空格、括号时可正常列出并播放（不得二次 URL 解码）。
3. 超过 3 层的目录不会被无限递归，最多 3 层。

#### FR-04 播放与续播（P0）✅

**描述**：内置 ExoPlayer 直读 SMB，支持暂停、快进/快退 15 秒、续播。

**规则**
- 每 3 秒批量落盘播放位置；再次进入从上次位置继续。
- 进度 ≥ `passRatio`（默认 92%）标记完成。
- 遥控器：OK 暂停/继续；左右 ±15 s；返回退出。
- 播放期间暂停轮询与封面加载（`SmbPlaybackContext.playing`），避免抢连接。

**AC**
1. 1080p H.264 起播 ≤ 2 s（正常网络，实测 1.4 s）。
2. 中途退出再进入，从上次位置继续（误差 ≤ 5 s）。
3. 播放中每 15 s 的片单轮询不得造成卡顿或断流。

#### FR-05 每日必看门禁（P0）✅

**描述**：`gate: true` 的分区为「每日必看」；`requires: "<key>"` 的分区在该 gate 全完成后解锁。

**规则**
- 完成判定：条目进度 ≥ `passRatio`，或手动看完（进度到结尾）。
- 未完成时，被锁分区卡片显示锁标 +「还差 N 个才解锁」。
- 家长可「这次先跳过必看」（仅本次会话有效，重启恢复）。
- 无 gate 分区时，所有分区随时可看。

**AC**
1. daily 5 条全部完成后，动画片/纪录片/学习三个分区立即解锁且可进入。
2. 未完成时点锁住的卡，提示「先做完上面那 N 个，就能看了」，不进入。
3. 「这次先跳过必看」后立即解锁；重启 App 后恢复限制。

#### FR-06 打卡墙（P1）✅

**描述**：当天必看全部完成时自动盖章；月历可翻页，显示连续天数与最长连击。

**规则**
- 盖章幂等：同一天只盖一次。
- 连续天数按自然日计算，中断即归零；历史最长连击单独保存。
- 进入奖励页即可查看，主界面完成后弹鼓励语。

**AC**
1. 首次完成必看，当天格子出现印章，连续天数 +1。
2. 同一天重复看完不会重复盖章。
3. 中间漏了一天，连续天数从漏掉那天起归零（最长连击保留）。

#### FR-07 勋章墙（P1）✅

**描述**：10 枚成就勋章，按累计打卡、连击、观看时长、视频数解锁；新解锁在主界面按钮挂小红点。

| 勋章 | 条件 |
|---|---|
| 启程之星「初」 | 首次完成每日必看 |

#### FR-08 可用时段与每日时长（P0）✅

**描述**：工作日/周末可分别设时间窗；每日真实播放时长上限；超限或时段外锁屏。

**规则**
- 时间窗支持 `"17:30-20:30"`、`["17:30","20:30"]`、`{"start","end"}` 三种写法；结束 < 开始视为跨零点。
- 不写 `weekend` → 沿用工作日；`[]` → 周末全天。
- `dailyLimitMinutes: 0` = 不限；只统计真实播放时长，暂停/缓冲不计。
- 锁屏：左 42% 大倒计时（隔几米可读），右 58% 学习角；家长 PIN 可放行 15 分钟。
- 设置页本身不受锁屏遮挡（家长多在改时段时被锁）。

**时长口径（R-07 的实现，2026-11-10 重构）**
- 全应用只有一个计时来源 `WatchClock`：`start(owner)` / `stop(owner)` + 1 秒 tick，单一 owner
  令牌；换 owner 自动结算旧的，重进播放页不会重复计。
- 每 10 秒落盘；`watch_<day>` 是总账，`ext_<day>` 是外部应用明细（为「外部应用计时」预留）。
- 播放页只负责在 `onIsPlayingChanged` 里 start/stop —— 暂停与缓冲天然不计时。

**时钟守卫（R-08 的实现，2026-11-10 新增）**
- 日期键统一由 `ClockGuard` 提供，不允许业务代码各自 `SimpleDateFormat`。
- 墙上时间被改（回拨 > 5 分钟或大跨度前跳）时，按「上次可信时间 + 真实流逝」继续算，
  日期不会跳到明天、当日用量不会归零；改回正确时间后自动解除，无需人工干预。
- 当日已用量取 `max(记录值, dayMaxUsed)`，只增不减。
- 放行类倒计时（临时放行 / 儿童锁放行 / 应用放行）改用 `elapsedRealtime` 计时，
  同时保留墙上截止时间，两个剩余量取小 —— 既防「改日期续命」，也防重启后 `elapsedRealtime`
  归零导致放行永不结束。

**背景（实机确认）**：`dumpsys usagestats` 显示 `com.cibn.tv` 当天 `totalTime=2:01:27`、
`appLaunchCount=8`，每 30 分钟放行窗口到期拉回后立刻又点进去；同期 `watch_<day>` 只涨了
小剧场内的 6 分钟，50 分钟上限**从未触发**。四个漏洞叠加：外部时长不入账、点应用入口不查门禁、
`current == null` 时锁屏盖不上、本地 `kiosk` 键缺失导致拉回根本没启用。

**规则**
- 账本统一：外部会话每 5 秒写入 `watch_<day>`，同时写 `ext_<day>` 明细；`GateKeeper` 不改。
- 探针三态 `STILL_IN / LEFT / UNKNOWN`：只看会话窗口内最后一次 `MOVE_TO_FOREGROUND` 的包名；
  **长时间无事件 ≠ 已离开**，静置期间继续计时，靠放行窗口到期或回前台钩子结算。
- 有 `PACKAGE_USAGE_STATS` 授权走精确计时（结算用 `totalTimeInForeground` 增量纠偏，偏差 > 20% 以系统值为准）；
  无授权降级 C：进入即预扣 `apps.maxMinutes`，结算退还差额，设置页标注「估算扣时」。
- 结束信号三个：探针 `LEFT`、`appLaunchActive()` 变 false、自己界面 `onActivityResumed`；
  三者都调同一个幂等 `settle()`。**顺序必须是「先结算 → 再 `clearAppLaunch()` → 再拉锁屏」**。
- 点应用入口前先查 `GateKeeper.status()`；限额用尽 / 时段外直接拒绝，不能靠跳到别的 App 绕过。
- 孩子在第三方 App 里（`current == null`）且门禁不可用时，前台守卫主动把主界面拉回来盖锁屏；
  这条**与 `features.kioskPullback` 无关**，体验开关不能关掉硬规则。
- 全链路 `elapsedRealtime` + `ClockGuard.day()`；不新增线程 / 定时器 / 服务，复用 `KidApp.tick` 的 1 秒节拍。
- `features.extWatchMs=false` 时全程不计时、不预扣，行为与旧版一致（15 秒回滚）。

**AC**
1. 从应用入口进优酷 10 分钟后回来，`watch_<day>` 增加 600±60 秒，`ext_<day>` 同值。
2. 优酷前台静置 5 分钟无任何事件，时长继续累计，不误判退出。
3. 限额用尽后再点应用入口被拒绝；已在第三方 App 内则用尽后 3 秒内被拉回并盖锁屏。
4. `features.extWatchMs=false` 时不计时、不预扣；改回 `true` 15 秒内恢复。
5. 撤销 `appops` 授权后进应用，设置页显示「估算扣时」，看 2 分钟后退出退还剩余预扣。
6. 外部应用启动失败（已卸载）时预扣全额退还。
7. 时段到点瞬间退出外部应用，该段时长完整落账，不因 `clearAppLaunch()` 丢失。

#### FR-24 远程控制卡 `control.json`（P0）✅（2026-11-10 新增，Wave 1）

**描述**：家长在网页控制台点按钮，电视 15 秒内响应「立即锁屏 / 解锁 / 加时 / 暂停」，并回写回执。

**规则**
- 文件与 `tv.json` **分开**：`data:curated/control.json`（指令）、`data:curated/control.ack.json`（回执）。
  家长手改控制指令不可能碰到片单。
- 字段：`lockNow`（bool）、`addMinutes`（int，0–240）、`pauseNow`（bool）、`updatedAt`（ISO 8601 带毫秒）。
  **`lockNow` 字段存在且为 `false` = 显式解锁**；字段缺失不等于解锁，避免旧指令误解锁。
- 幂等键 `updatedAt`，缺字段时退化为原文 hash；同一条指令重复轮询不重复执行。
- `lockNow` 必须落到 `GateKeeper.Reason.REMOTE`，否则全局 1 秒守卫会在下一秒把锁屏 finish 掉。
- `addMinutes` 同时清掉远程锁定并 `grantTemp(n)`；倒计时仍按「墙上 + `elapsedRealtime` 取小者」（R-18）。
- `pauseNow` 用单调版本号 `RemoteControl.pauseVersion`，播放页 ticker 比对后 `pause()`；
  播放器不在前台时也不丢指令。
- 坏 JSON / 文件不存在：忽略、不崩、**不影响片单同步**；同一份坏内容只打一条日志（EX-21）。
- 播放期间也照常轮询；复用 `PlaylistSync` 的后台单线程池，不新增线程或服务。
- `features.remoteControl=false` 时完全不读 `control.json`；默认 **关**，家长在编辑器「规则」页打开。

**AC**
1. 发 `lockNow=true`，15 秒内前台变 `LockActivity`，`control.ack.json` 的 `actions` 为 `["lockNow"]`。
2. 20 秒后重复轮询，执行日志仍只有 1 条。
3. 发 `lockNow=false` 解锁；发 `addMinutes=10` 加时且播放页显示「临时放行还剩 10 分钟」。
4. 发 `pauseNow=true` 时播放暂停；`control.json` 写坏 JSON 时片单仍能自动更新（EX-21）。

#### FR-25 设置写回失败阻断 + 未同步标记（P1）✅（2026-11-10 新增，Wave 1）

**描述**：电视上改设置写不进 NAS 时，必须阻断并明确告知，绝不出现「界面改好了、下次同步悄悄变回去」。

**规则**
- `PlaylistWriter.patch()` 失败时返回 `pendingText`（当时本想写入的完整 `tv.json`）与
  `baseHash`（失败前读到的远端指纹）；连读都没读到时 `pendingText` 为空。
- 失败时**不调用 `after()`**：本机保持 NAS 上的旧值；设置页停留原页、顶部挂红色错误条，
  并置 `Store.unsynced_edit=true`（PRD EX-22）。
- 错误条一直挂到家长处理完；新增「未同步的修改 / 重试保存到 NAS」入口，弹窗三选
  「覆盖 NAS / 放弃这次修改 / 稍后再说」（30 秒节流，主动点重试可跳过）。
- 重放前**重新读一次 NAS**，与 `pendingBaseHash` 比对：期间家长在网页上改过片单就拒绝覆盖，
  宁可让他重设一次，也不能抹掉别人的改动。
- 有未同步修改时 `PlaylistSync.applyToLocal(skipSettings=true)`：**片单条目照常刷新，

- 放弃 / 重放成功后清 `unsynced_*`；成功后只针对 `reason=settings*` 补一次设置页渲染，

**AC**
1. NAS 写保护时在电视上改时段：留在原页、红色错误条可见、`unsynced_*` 六键齐全，
   本机与 NAS 的设置都保持旧值。
2. 未同步期间从网页改片单：日志显示「跳过设置下发」，本机家长设置不变、错误条仍在。
3. NAS 期间被改过后点「覆盖 NAS」：重放被拒且 NAS 内容不被覆盖。
4. 点「放弃这次修改」：错误条与重试行消失、`unsynced_*` 清空。
5. 写保护解除后重放成功：NAS 与本机同时变为新值，错误条消失，设置页即时显示新值。

#### FR-32 完成必看自动奖励加时（P2）✅ 代码完成，实机待验（2026-11-11 新增，Wave 3）

**描述**：`schedule.rewardMinutes`（默认 0 = 关闭，上限 120）。当日必看全部完成 → 今天的**额度**加 N 分钟，
并提示「今天全部完成，奖励 10 分钟，可以多看一会儿啦」。

**为什么不复用「临时放行」**：临时放行是「从此刻开始倒计时」的窗口，家长再点一次放行就会覆盖它；
孩子做完任务先去吃饭、晚上回来再看，那 10 分钟已经过期 —— 那不叫奖励。
所以奖励写进当天额度 `bonus_<day>`，与手动放行（`tempUntil`）分开计数，谁也不会覆盖谁。

**四条边界**：
1. **只加额度不改时段**：时段外奖励再多也进不去；
2. **一天只发一次**：`reward_<day>` 标记，重绘 / 切页面不会重复发；
3. **只升不降**：当天把 10 调成 20 就是 20，不是 30（`RewardMath.bonusAfter` 取大值）；
4. **没有必看分区时不发**：`gateTotal == 0` 视为「没有任务」，否则等于天天白送时间；
   基础上限为 0（不限制）时 `0 + 10` 仍按不限制处理，不能凭空造出一个 10 分钟上限。

**AC**：配 10 分钟后完成全部必看，首页时长显示 `x/(上限+10) 分钟（含奖励 10 分钟）`；
再刷新一次不重复发；把上限改成 0（不限制）后奖励不产生限额；改电视日期拿不到第二天的奖励。

#### FR-33 异常落盘与自诊断（P1）✅ 代码完成，实机待验（2026-11-11 新增，Wave 4 / OPT-17）

**描述**：孩子说「它自己变回去了」、家长说「今天又没锁屏」，这两句话是没法排查的。
`KidApp.tick` 原来是个空 `catch` —— 守卫确实不会把应用搞崩，但也把唯一的线索咽掉了。
本需求把「本不该发生但没崩」的异常与真正的崩溃都留下记录，**家长不用连电脑**也能给到证据。

**两层落盘**：
1. **本地**：`filesDir/diag/tv-yyyyMMdd.txt`，`record()` 同步追加（毫秒级），断网 / NAS 挂 / 下一秒就崩都在；
2. **NAS**：由 1 秒心跳驱动，攒够 60 秒在后台合并上传到 `data:curated/logs/tv-yyyyMMdd.txt`。

**为什么不在 `catch` 里直接写 NAS**：心跳 1 秒一次，写 NAS 是一次网络往返 ——
那等于每秒在 UI 线程等网络；而且 NAS 不通恰恰是最容易出异常的时刻，那时候写不上去，线索就没了。

**容量与保留**：单文件 200 KB，超了**整行**丢最旧的并在开头插一句「更早的日志已滚动丢弃」；
按日期保留 7 天（今天 + 前 6 天）；本地最多攒 300 条，超了丢最旧的文件。

**去重**：同一处异常（标签 + 异常类 + 第一个栈帧）60 秒只记一条，被合并的次数写成「又出现了 N 次」，
否则一秒一条、200 KB 十分钟就满。

**崩溃兜底**：`Thread.setDefaultUncaughtExceptionHandler` 先写日志再**原样交回系统**（该崩还是崩）。
带着记错的账继续跑比崩掉更糟。

**入口**：设置页「维护 → 诊断日志」：待上传条数、上次上传时间、最近几条、立即上传、清空。

**AC**：人为触发一次心跳异常后，本地立刻有记录，约 1 分钟内出现在 NAS 的 `logs/` 下；
断网期间记录只增不减，恢复后自动补传；`logs/` 目录不存在时自动创建；
7 天前的 `tv-*.txt` 被清掉；同一异常连抛 10 次只产生 1 条；其余功能与耗时无可感知变化。

## 9. 关键业务规则（实现契约）

| ID | 规则 | 说明 / 边界 |
|---|---|---|
| R-01 | 条目 id 由路径派生 | 形如 `p:folder` / `p:file` / `p:app` 加路径；**不得用数组下标**（会导致封面/进度错位）。旧键由 `migrateLegacyKeys` 一次性迁移 |
| R-02 | 路径相对 `nas.share` | 中文直接写，不 URL 编码；`/` 分隔；自动剥离 `共享名/`、`smb://host/share/` 前缀 |
| R-03 | 不在 `Uri.path` 后再 URLDecode | `+` 必须保留原义，否则整目录失效 |
| R-04 | 完成判定 | 进度 ≥ `passRatio`（默认 0.92）；`passRatio` 以 Double 写入，避免浮点脏值 |
| R-05 | 必看完成 | gate 分区内**全部**条目 done；随之解锁 `requires` 指向的分区 |
| R-06 | 打卡幂等 | 自然日唯一；连续天数按自然日；最长连击单独存 |
| R-07 | 时长统计 | 仅播放中累计（暂停/缓冲不计）；单一来源 `WatchClock`，10 s 落盘；`watch_<day>` 总账 + `ext_<day>` 明细；外部应用会话走同一本账（FR-22） |
| R-08 | 时段判定 | 左闭右开；结束 < 开始视为跨零点；`weekend` 缺省沿用工作日，`[]` = 全天 |
| R-09 | 放行优先级 | 家长临时放行 > 时段/时长限制；放行期间不弹锁屏、不被前台守卫拉回 |
| R-10 | 应用入口解锁 | `showAfterDaily` 且存在 gate 分区 → 必看完成后可用；否则一直可用 |
| R-11 | PIN | 4–8 位数字；明文存于 `tv.json`；仅防孩子随手解锁 |
| R-12 | 密码占位符 | 空 / 全星号 / `__KEEP_NAS_PASSWORD__` → 沿用旧密码，电视端同样保护 |
| R-13 | 单一事实来源 | 时段/上限/PIN/apps 以 NAS `tv.json` 为准；电视本地只存运行态（进度、打卡、勾选、放行） |
| R-14 | 写回必须合并 | 读远端最新 → 只改目标字段 → 备份 → 原子写 → 回读校验 |
| R-15 | 播放优先级 | 播放期间暂停轮询与封面加载，避免抢 SMB 连接 |
| R-16 | 日期键唯一 | 所有日期键走 `ClockGuard.day()`；墙上时间跳变（回拨或大跨度前跳）时按「上次可信时间 + 真实流逝」冻结，改回后自动解除 |
| R-17 | 当日用量只增不减 | 取 `max(watch_<day>, daymax_<day>)`；清记录、改日期都不能让今天「重新有时间」 |
| R-18 | 放行倒计时不看墙上时间 | 临时放行 / 儿童锁放行 / 应用放行另存 `elapsedRealtime` 截止点，与墙上截止点取剩余较小者 |
| R-19 | 功能开关兜底 | `features` 缺字段 / 类型错一律读默认值（新功能默认关、老行为与已确认 bug 修复默认开），开关本身不得抛异常 |
| R-20 | 外部时长只入一次账 | `ExtWatchTracker` 是唯一 owner；`settle()` 幂等；进入前 `WatchClock.stopCurrent()` 清掉播放页残留 owner |
| R-21 | 信息缺失不等于离开 | 探针 `UNKNOWN` 保持会话；只有 `LEFT` / 放行窗口到期 / 回前台才结算，静置看片不漏记 |
| R-22 | 宁可多扣不漏记 | 无 usage 授权时先预扣 `maxMinutes` 再按实测退还；精确模式结算的负差额不强退（dayMax 只增不减） |
| R-23 | 门禁不能被体验开关关掉 | `kioskPullback` 只管「防切走」体验；限额 / 时段的兜底拉回独立执行，且点应用入口前必须先查门禁 |
| R-24 | 冷启动补下发 | `PlaylistSync.init()` 用缓存清单幂等重放 `applyToLocal()`，不读 SMB；防止升级后本地缺 `kiosk` / `features` |
| R-25 | 预告不参与门禁 | `TimeNotice` 只读账本算文案；到点仍由 `GateKeeper` + `stopForLock()` 决定锁不锁，预告不得成为第二条计时或放行动作 |
| R-26 | 远程指令幂等且分文件 | 控制指令在 `control.json`、回执在 `control.ack.json`，不碰 `tv.json`；`updatedAt` 去重；`lockNow` 必须落成 `GateKeeper.Reason.REMOTE`，否则守卫会拆掉自己的锁屏 |
| R-27 | 写回失败不静默 | 失败即置 `unsynced_edit` 并留原页；有未同步修改时片单可刷新但设置不下发；重放前必须比对远端基线指纹，指纹不符就拒绝覆盖 |
| R-28 | 连播不得绕开门禁 | `autoNext` 只是体验开关；`maybeAutoNext()` 与倒计时每秒都查 `GateKeeper`，家长暂停 / 限额到点立刻停，`stopForLock()` 优先于连播 |
| R-29 | 队列不占用 SMB 主连接 | 整季队列在剧集页一次编码、随 Intent 传递；播放结束不再列目录，避免半死连接把剧集页和播放一起挂住 |
| R-30 | 动态分区的 key 仍路径派生 | 「继续看」分区 key 固定 `p:continue`，但分区内条目一律沿用原 key；`Store.notePlayed()` 与进度落盘分开，避免排序错位 |
| R-31 | 备份不得把记录弄小 | `StateMerge.merge` 同键取大值、打卡取并集；导入幂等，重复导 / 导一半断电再导都不会让记录变小。因此它不能用来「回退」，回退只走设置页的显式路径 |
| R-32 | `pm clear` 后仍读得到备份 | 清数据会连 `nas_*` 一起清空，`StateBackup` 与 `Repo.load()` 一样退回 `Store.DEFAULT_NAS`；否则「重装能恢复」是空话。另外本地快照为空时绝不回写 |
| R-33 | 奖励记额度、不记放行 | 完成必看的奖励写 `bonus_<day>` 并加到当天上限（`GateKeeper.limit`），**不得**复用 `tempUntil` —— 放行窗口会过期、会被下一次手动放行覆盖；日期键走 `ClockGuard.day()` |
| R-34 | 周报只读且不读 NAS | 周报所有数字来自本地 prefs；`ext_<day>` 必须夹到不超过 `watch_<day>`（防手改后画出负段）；没有数据就显示空状态，不显示 0；平均只按有记录的天算 |
| R-35 | 日志两段式、绝不拖累主流程 | 异常先同步落本地、再由心跳后台传 NAS；`record()` 自身任何失败只 `Log.w`，不向上抛；同一指纹 60 秒一条；滚动整行丢、按 UTF-8 字节计上限；`logs/` 只删 `tv-yyyyMMdd.txt`，其它文件一律不动；读失败（非「文件不存在」）不得当空文件覆盖 |
| R-36 | 界面文案只在 strings.xml | 新增/修改面向用户的中文必须加进 `res/values/strings.xml` 并用 `getString`（object 里用 `activity.getString`）；带变量的句子必须用位置占位符 `%1$s / %2$d`，不得用字符串拼接；教学数据（`data/builtin/`）与日志文本不进资源；`tools/check_strings.py` 的预算只降不升 |

### 10.3 `state.json`（NAS：`data:/curated/state.json`）

电视自动写的打卡与进度备份，**独立文件**，家长手改片单碰不坏它（见 FR-30）。
明文 JSON，出问题可以直接打开看，删掉也会自动重新生成。

```json
{
  "version": 1,
  "savedAt": 1762851234567,
  "savedAtText": "2026-11-11 16:05",
  "note": "电视自动备份的打卡与播放进度，重装后可恢复；删掉也没关系，会重新生成",
  "stamps": ["2026-11-09", "2026-11-10"],
  "longs": {
    "watch_2026-11-11": 1200000,
    "ext_2026-11-11": 300000,
    "pos_p:/cartoon/01.mp4": 480000,
    "dur_p:/cartoon/01.mp4": 600000
  }
}
```

- `version` 大于本版 App 支持的值时整份忽略（旧 App 不猜新字段）。
- `stamps` 只认 `yyyy-MM-dd`，最多 400 天；`longs` 只认白名单前缀、非负、键长 ≤200、最多 5000 项。
- 读不到 / 写不进都只影响恢复能力，**不影响播放与门禁**。

## 11. 非功能需求

### 11.1 性能（实测基线，2.5 GB RAM / 1080p）

| 项 | 目标 | 实测 |

### 11.2 兼容性

- 电视：Android TV / 国产 Android 电视，minSdk 24，armeabi-v7a + arm64-v8a；主测海信 55E3F-MAX（Android 9，VIDAA）。

### 11.3 可靠性

- 任一次 SMB 读挂死不得拖死全局（硬超时 + 关 socket + 重连）。
- 播放三层自愈；仅不可恢复错误直接失败。
- 保存片单必须原子写；禁止读到半截 JSON。
- 电视端设置写回失败**不得**修改本地显示。

### 11.4 安全与隐私

- `tv.json` 含 NAS 明文密码与 PIN，只放在自家 NAS；不入 Git、不外传。
- 控制台默认只听 `127.0.0.1`；开 `--lan` 后所有 API 需访问码；连错 5 次锁 5 分钟。
- 访问码存浏览器 localStorage，不进 URL / 历史 / 代理日志。
- 禁止把 8765、5555 映射到公网；外网只用 Tailscale / UGREENlink / Cloudflare Access。
- APK 内凭据为兜底，仓库只留占位符。

### 11.5 可维护性

- 字段手册（CONFIG.md）、JSON Schema、内置题库自检脚本、编辑器自检（`--self-test`）。
- 所有系统级改动均附撤销命令。
- 关键链路（轮询/广播/写回）有日志与「电视状态」可视化诊断。

### 11.6 成本

- 零订阅、零云服务费；仅家庭 NAS 电费与带宽。
- 外网方案 A 免费；B 依赖已有绿联账号。

## 12. 约束与已知限制

### 12.1 技术约束

- 电视只有 2.5 GB RAM，/data 可用曾低至 842 MB（装 Kodi 时 877 MB）→ APK 控制在 ~27 MB，不引入重型框架。
- Android 9 不支持 scrcpy 音频转发（需 11+）。
- smbj 的 `withTimeout` 管不住 TCP 半开与 oplock 等待 → 必须自建 deadline。

### 12.2 平台限制（不做承诺）

| 限制 | 影响 | 现状 |
|---|---|---|
| Home 键由系统独占 | 只改 App 拦不住 | 通过“设为默认桌面 + 前台守卫”解决 |
| VIDAA 不派发 `BOOT_COMPLETED` 给第三方 | 开机停原生桌面 | 按一次 Home 进入；已接受 |
| 输入源 / 直播 / 电源为红外/固件级 | 应用收不到按键 | 物理遮挡或简易遥控器 |

5. 电视端 `tv.json` 里 `schedule.pin` 为历史冗余字段，以顶层 `pin` 为准（建议后续清理）。

## 17. 附录

### 17.1 术语

| 术语 | 含义 |
|---|---|
| 分区 / section | 海报墙上的一行，如「今天要看的」 |
| 条目 / item | 一张海报卡：单集、整季或应用 |
| 必看 / gate | 每天必须先完成的分区 |
| 门禁 / requires | 被必看分区锁住的其他分区 |
| frontier | 必看视频「真正连续看到的最远位置」 |
| 放行 | 家长临时解除时间/儿童锁限制的一段时间 |
| 单一事实来源 | NAS 上的 `tv.json` |

### 17.2 遥控器速查

| 场景 | 按键 |
|---|---|
| 主界面 | 上下选分区、左右选片、OK 进入 |
| 播放 | OK 暂停、左右 ±15 s、返回退出 |
| 锁屏 | 数字键输 PIN、◀▶ 翻学习卡、播放键暂停轮播、菜单键输 PIN |
| 家长 | 菜单键 → PIN |
| 奖励页 | 信息 / 指南键直达 |

### 17.3 错误码提示

| 段 | 含义 | 建议 |
|---|---|---|
| 2xxx | NAS 读取失败 | 查 445、账号、共享名 |
| 3xxx | 文件头没读完整 | 重试；仍失败查文件完整性 |
| 4xxx | 解码器不支持 | 转码（如 HEVC 10bit / DTS 音轨） |
